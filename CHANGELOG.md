# Changelog

## 1.3.4
- Honeypot больше не удаляет и не заменяет клиентские маски телефона Simple, Inputmask или UniShop.
- Исправленная владельцем магазина маска остаётся единственным источником форматирования; модуль выполняет только серверную проверку итогового номера.
- Сохранены поздняя проверка SmartCaptcha, безопасная диагностика Yandex, отдельная ошибка телефона и восстановление регистрации после rate-limit.


## 1.3.3
- Для российской регистрации конфликтующие маски Simple/Inputmask/UniShop снимаются с поля телефона; модуль сам принимает `8XXXXXXXXXX`, `7XXXXXXXXXX`, `+7XXXXXXXXXX` и десятизначный номер с `9`.
- Номер приводится к виду `+7 (999) 999-99-99` без потери последней цифры при вводе, вставке и автозаполнении браузером.
- Некорректный обрезанный номер вроде `+(792)601-09-13` по-прежнему блокируется сервером как `invalid_phone`.
- Ошибка телефона выводится отдельным понятным сообщением и не увеличивает антибот-счётчик rate-limit.
- Старая IP-блокировка регистрации может быть безопасно снята успешной SmartCaptcha; без действительного Yandex-токена обход невозможен.


## 1.3.2
- Проверка Honeypot/SmartCaptcha в Uni Login Register и стандартной регистрации перенесена после обычной валидации формы.
- Устранено PHP-предупреждение о неинициализированной переменной в AJAX-проверке, которое могло повреждать JSON-ответ.
- Исключена ранняя проверка основной CAPTCHA Honeypot, расходовавшая одноразовый `smart-token` до проверки e-mail, пароля и согласия.
- В журнал события `yandex_failed` добавлена безопасная техническая причина (`missing_smart_token`, `http_...`, `curl_...`, `status_failed`) без ключей и токена.

## 1.3.1
- Добавлена защита реальных маршрутов регистрации `account/simpleregister` (Simple) и `extension/module/uni_login_register/register` (UniShop2).
- Honeypot и встроенная Yandex SmartCaptcha теперь выводятся в формах Simple и Uni Login Register, включая AJAX-модальное окно.
- Серверная проверка телефона поддерживает как `telephone`, так и вложенное поле `register[telephone]`.
- Все маршруты регистрации используют единый rate-limit scope; счётчик увеличивается только при антиспам-отказе, а успешная проверка снимает накопленные ошибки.
- Одноразовый Honeypot-токен поглощается только после фактического создания клиента, поэтому повторная AJAX-отправка после обычной ошибки формы больше не ломается.
- Успешное прохождение `registration_passed` записывается после создания клиента.
- Виджет и серверная проверка переведены на актуальные адреса `smartcaptcha.cloud.yandex.ru`; проверка токена выполняется POST-запросом.

## 1.3.0
- Добавлен автономный Yandex SmartCaptcha-блок в настройках Honeypot.
- Добавлены два режима ключей: использовать стандартный модуль Yandex либо собственные Site key / Secret key Honeypot.
- Добавлен отдельный переключатель Yandex SmartCaptcha для страницы регистрации.
- Добавлена обязательная серверная проверка `smart-token` через API Yandex для встроенного режима.
- Исключено дублирование виджета, если Yandex уже выбран основной CAPTCHA для регистрации.
- Добавлена серверная проверка телефона при регистрации: допустимые символы, 10–11 цифр после нормализации, опциональный российский формат.
- Добавлена причина журнала `invalid_phone`.
- Добавлено опциональное журналирование успешных регистраций (`registration_passed`).
- В админке добавлена подсказка: обязательная сложная задача/картинки настраиваются в Yandex Cloud для используемого Site key.

## 1.2.0
- Усилена защита регистрации независимо от списка страниц основной CAPTCHA.
- Добавлены два honeypot-поля, JavaScript-проверка и привязка токена к User-Agent.
- Минимальное время заполнения по умолчанию увеличено до 5 секунд.
- Добавлен срок жизни токена формы.
- Добавлен rate limit по IP/route с временной блокировкой.
- Добавлены новые причины блокировки в журнале: missing_session, expired_token, client_mismatch, missing_trap, js_check, rate_limit, yandex_failed.
- Для регистрации автоматически подключается Yandex SmartCaptcha, если стандартный модуль Yandex CAPTCHA включён и в нём уже настроены site key и secret.
